# 会话收尾检查清单

> **触发条件**：识别到结束信号即启动（不等用户明说"会话结束"）。
> 触发词：「存档」「下次继续」「换个新窗口」「今天先到这」「先这样吧」「收尾」「结束」等
> 任何表示当前会话即将结束或工作转移的措辞。
>
> **核心原则**：宁可多做不可漏。收尾做了没坏处，漏了要用户补救。
>
> **⚠️ 第一件事：读本文件按 8 步清单收尾**——不要凭记忆只做几件事。
> 历史教训：多次因"凭记忆收尾"漏了 index.md 同步或分支清理。

## 检查清单

> 8 步(0-7)。子工程多一步回流处理(5.5)。

### 0. 检查分支状态 + 合并 + 清理

- [ ] 检查当前分支（`git branch --show-current`）+ 有无未提交代码
- [ ] feature 分支合并 master 前 / 里程碑代码冻结前,**必须用 `zcode-pr-review` Skill 跑深度 review**
  (多 agent 并行,不允许用单个轻量 reviewer 替代;历史教训:M1 收尾时它发现了置信 92 的 Critical bug)
  - master 上的小改动(纯文档/单行修复)可豁免
- [ ] 已合并的 feature 分支清理删除

### 1. 进度记录 → `progress.md`

- [ ] 更新「当前状态」段（版本/测试数/lint —— 唯一真相源）
- [ ] 更新本会话 Tier 段（commit 明细 + 验证结果 + 反思）

### 2. 索引同步 → `index.md`

- [ ] 新文档/新目录/新模块 → 立刻更新 index.md
- [ ] 状态性内容（进度段/Tier 列表）→ 会话结束统一更新

### 3. TODO 同步 → `TODO.md`

- [ ] 完成的 TODO 标记完成
- [ ] 新发现的 TODO 立项
- [ ] 更新「下次会话目标」

### 4. 启动包更新 → `new-session-starter.md`

- [ ] 更新当前状态指针 + 下次目标指针
- [ ] 更新启动咒语（本次目标 → 下次目标）

### 5. 代码索引工具 sync

- [ ] 若用 CodeGraph：`codegraph sync`
- [ ] 若用其他索引工具：对应 sync 命令
- [ ] 无索引工具则跳过

### 5.5 🔴 回流候选处理（子工程专属）

> **本工程是模板的子工程时才做**（模板自身无此步骤）。
> 子工程职责是**识别 + 记录 + 整理提案**，不直接改母工程仓库。详见 `wiki/process/template-evolution-guide.md`。

- [ ] 读 `wiki/dev/REFLUX-CANDIDATES.md`「待评估」，逐条过
- [ ] 每条判定：回流 / 留子工程 / 丢弃
- [ ] 对确认回流的：整理「回流提案文档」落盘到 `wiki/dev/reflux-proposals/<主题>.md`
      （模板见 `wiki/dev/reflux-proposals/README.md` 或 `template-evolution-guide.md`）
- [ ] 处理完的候选条目移到「已处理」，保留追溯
- [ ] **问自己一句**：这次开发有没有长出什么通用的东西没记进候选池？（对照 `reflux-signals.md` 信号清单再扫一遍）
- [ ] 提示用户：提案文档已就绪，请带到母工程会话执行回流

### 6. 核查 + 显式报告用户

- [ ] 启动子 agent 核查收尾完整性（progress/index/TODO/starter 都已更新）
- [ ] **主动向用户报告核查结果**（"progress 已更新 + TODO 下次目标已更新 + index/starter 确认 + 分支已清理"）
- [ ] 让用户不用自己检查

### 7. 流水账（按需）

> **录入位置**：项目根目录 `决策分析/` 文件夹（不是个人目录，不是 wiki/）。
> **必读 `决策分析/README.md`** 的「录入规则」段——含触发条件、文件命名、格式模板、质量底线。
> 不要自建目录，不要凭记忆写，严格按 README 的 4 步录入流程执行。

- [ ] 读 `决策分析/README.md` 录入规则
- [ ] 按 README 格式新建流水账文件（编号递增 + 日期标识）
- [ ] 保留用户原话 + commit hash + 决策上下文（为什么这么决策，progress 只记结果）
- [ ] 更新 `决策分析/README.md` 当前状态段 + 目录结构表

## 常见遗漏（历史教训）

| 遗漏类型 | 后果 | 预防 |
|---------|------|------|
| 凭记忆收尾漏 index.md | 用户找不到新文档 | 步骤 2 必做 |
| 未提交代码就结束 | 代码丢失 | 步骤 0 先查 git status |
| 漏分支清理 | 分支堆积 | 步骤 0 清理 |
| 不报告核查结果 | 用户自己检查 | 步骤 6 主动报告 |

## 执行节奏

读完本清单 → 逐项执行 → 全部完成后报告 → 等用户确认结束。
