# 知识库内容规范

> 写/改 wiki 内容前（新建文档 / 改文档状态 / 归档文件）先读本文件，防止知识库膨胀混乱。

## §一 核心原则（3 条）

1. **每份内容只有一个家**——根据目录职责表放进唯一正确的目录
2. **状态变了必须迁家**——文档状态变化（计划→完成 / active→archived）必须迁移到对应目录
3. **单一真相源**——信息只写一处，别处放指针。状态数字（版本/测试数）只在 progress.md

## §二 目录职责表

| 目录 | 职责 | 典型文件 | 归档时机 |
|------|------|---------|---------|
| `architecture/` | 架构 / 约束 / 决策原则 | engineering-principles / constraints / overview | 不归档（持续维护）|
| `process/` | 工程流程清单 / 协作规范 | code-review-checklist / session-checklist | 不归档 |
| `dev/` | 开发进度 / TODO / 启动包 | progress / TODO / new-session-starter | 完成的 plan 归档 |
| `research/` | 调研报告 / 踩坑经验 | poc 经验 / 方案调研 | 调研结论沉淀后归档 |
| 业务目录 | 业务设计 / 模块（业务工程起步时建）| 按业务领域组织 | 业务下线时归档 |

**归档目录**：`dev/archive/`（完成的 plan）/ `research/archive/`（沉淀完的调研）

## §三 文件命名规范

- 任务 plan：`<TODO编号>-<slug>-plan.md`（如 `001-sse-plan.md`）
- 专项计划：`<主题>-plan.md`
- 归档文件：移到对应 `archive/` 目录，文件名保持不变

## §四 反模式（5 个，必须避免）

1. ❌ **预创空目录**——没有内容不要建目录（空目录 = 未来混乱的种子）
2. ❌ **状态四处抄写**——版本号/测试数只在 progress.md，别处放指针（呼应核心原则 3）
3. ❌ **完成不归档**——任务完成后 plan 留在 dev/ 不归档（dev/ 只放活跃任务）
4. ❌ **迁移不修链接**——移动文件后不更新引用它的文档（产生死链）
5. ❌ **单文档膨胀**——一个文档超过 800 行不拆分（呼应工程纪律：文件 < 800 行）

## §五 操作流程速查

| 场景 | 操作 |
|------|------|
| 新建任务 | plan 放 `dev/`，更新 `index.md` + `TODO.md` |
| 任务完成 | plan 归档到 `dev/archive/`，更新 `progress.md` |
| 优化灵感 | 进想法池文档（不进 TODO）|
| 信息过时 | 直接更新（或加「⚠️ 重要更正」段，不删原文，呼应 §1.4）|

## §六 index.md 统管全局

`wiki/index.md` 是知识库"门面"，必须让读者了解到知识库拥有的所有内容。
新文档/新目录/新模块/新工具 → **立刻更新 index.md**（不等会话结束）。
